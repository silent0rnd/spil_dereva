# Спил Деревьев — заметки для разработки

Одностраничный лендинг услуги спила деревьев. React 19 + Vite + Tailwind v4 + `motion`.
Деплой — GitHub Actions на GitHub Pages, база `/spil_dereva/`.

```bash
npm run dev      # дев-сервер на :3000
npm run lint     # tsc --noEmit
npm run build    # прод-сборка
npm run images   # перегенерация WebP из исходников (локально, результат коммитится)
```

## Дизайн-система

Единственный источник правды — блок `@theme` в [src/index.css](src/index.css). Не заводите
значения цветов, радиусов и теней по месту.

**Цвет.** Палитра тёплая. Нейтрали — `ink-*`, а не Tailwind-овские `gray-*`. Холодный
`gray-*` в проекте запрещён: на песочных подложках он даёт тот самый «шаблонный» вид,
ради устранения которого шкала и заводилась. Проверка: `grep -rn "gray-[0-9]" src/`
должен быть пустым.

**Поверхности.** Ровно три, чередуются по странице:
`bg-white` → `bg-forest-50` → `bg-forest-950`. Полутонов (`/50`, `/40`, `/20`) у фонов секций
не бывает — из-за них раньше галерея выпадала из ритма.

**Радиусы.** Три токена, по назначению, без исключений:
- кнопка, инпут, мелкая плашка → `rounded-btn`
- карточка → `rounded-card`
- крупная панель (калькулятор, галерея, баннеры) → `rounded-panel`
- пилюля, аватар → `rounded-full`

`rounded-xl` / `rounded-2xl` / `rounded-3xl` не использовать.

**Тени.** `shadow-card`, `shadow-card-hover`, `shadow-panel`. Они тёплые (на базе
`forest-950`); нейтрально-чёрные тени Tailwind по умолчанию с этой палитрой конфликтуют.

**Шрифты.** Lora (display) поставляется только до 700, JetBrains Mono подключён до 700.
Поэтому `font-extrabold` и `font-black` на `font-display` и `font-mono` запрещены —
браузер синтезирует такой вес сам, и результат выглядит замыленным. Нужен больший акцент —
берите размер и `tracking`, а не вес. Шкала заголовков описана комментарием в `index.css`.

## Движение

Всё через `motion`. Три переиспользуемых кирпича в [src/components/ui](src/components/ui):

- `Reveal` — появление при въезде в вьюпорт. Для списков передавайте `delay={index * 0.07}`.
- `SectionHeading` — плашка + H2 + лид. Все секции обязаны использовать его, иначе снова
  расползётся копипаста, которая была в Services / Calculator / Gallery / Reviews.
- `CountUp` — счётчик. `startOnView` по умолчанию `true` (цифры доверия);
  для калькулятора передаётся `false`, чтобы число перекатывалось при каждом пересчёте.

**Осторожно с горизонтальными появлениями.** `Reveal direction="left|right"` на блоке
шириной во весь экран выносит его за вьюпорт во время анимации и на мобильных даёт
горизонтальный скролл. На всякий случай в `index.css` стоит `body { overflow-x: clip }` —
именно `clip`, а не `hidden`: `hidden` ломает `position: sticky` у карточки результата
калькулятора.

**`backdrop-blur` — только от `md:` и выше.** Это самое дорогое, что есть на странице:
блюр поверх движущегося фона пересчитывается каждый кадр. На мобильном под троттлингом
он один давал падение до 30 fps и кадры по секунде. Все места (шапка, бейдж и кнопка героя,
плашки галереи, панель звонка) уже переведены на `md:backdrop-blur-*` с более плотной
заливкой на узких экранах — визуально разницы нет. Замер: медиана 33.3 → 16.8 мс,
худший кадр 1217 → 150 мс. Не возвращайте негейтед `backdrop-blur`.

**Reduced motion.** Каждая анимация обязана деградировать. В `index.css` есть глобальный
`@media (prefers-reduced-motion: reduce)`, в компонентах — `useReducedMotion()`.
Правило: контент никогда не должен оставаться невидимым из-за того, что анимация не
выполнилась.

## Пасхалка — [ScrollTree.tsx](src/components/ScrollTree.tsx)

Дерево на правом поле страницы, которое спиливается по мере скролла: ветки отлетают по
одной, затем ствол, пень, фрезеровка, росток. Работает и как индикатор прогресса чтения.
Монтируется только от `xl` (≥1280px), под reduced motion рисуется статикой.

Два подводных камня, на которые уже наступали:

1. `transform` — зарезервированный проп у motion-компонентов SVG, передавать его бесполезно.
2. Пивот задаётся **только** через `originX`/`originY`, и motion трактует их как **долю**
   от transform-box, а не как пиксели. Для этого есть хелпер `pivot(x, y)` — он делит
   координаты viewBox на его размеры. Обычный `transformOrigin` motion перезатирает своим
   `50% 50%`, из-за чего всё вращается вокруг центра SVG.

Пороги срабатывания в `BRANCHES` и константах `TRUNK_CUT_AT` / `STUMP_GRIND_AT` /
`SPROUT_AT` подобраны под текущую длину страницы. Добавите или уберёте секцию — сверьте,
что этапы по-прежнему попадают в нужные блоки.

## Контент и ассеты

**Контакты** — только через `CONTACTS` в [src/data.ts](src/data.ts). Телефон раньше был
захардкожен в шести компонентах; при замене заглушки на реальный номер легко пропустить точку.

**Картинки.** Исходники — JPEG в `src/assets/images/`, но в компоненты они не импортируются.
`npm run images` генерирует WebP в двух ширинах и `manifest.json`; компоненты берут их
через `getImage(base)` из [src/lib/images.ts](src/lib/images.ts) по имени файла без
расширения. Хелпер отдаёт `src`, `srcSet` и интринсивные размеры — `width`/`height`
проставлять обязательно, иначе вернётся CLS.

`sharp` намеренно не участвует в CI: workflow делает только `npm install && npm run build`,
а `.webp` лежат в репозитории.

**Фотографии сгенерированы ИИ.** В кейсах два снимка на проект — это просто галерея, а не
пара «до/после»: сняты они в разных местах, и подписывать второй кадр как «после» нельзя.
При появлении настоящих фото с объектов их стоит заменить.

## Известные мелочи

- `before_wild_yard` и `after_clean_yard` больше нигде не используются (их потреблял
  удалённый `GALLERY_ITEMS`), но `import.meta.glob` в `images.ts` забирает все `.webp` из
  папки, поэтому ~0.8 МБ попадает в `dist` без загрузки пользователем. Не нужны — удалите
  исходники и перезапустите `npm run images`.
- Ссылка «Посмотреть отчет на старом сайте» в галерее ведёт на внешний spilservis.ru.
